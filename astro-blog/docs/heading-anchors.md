# 小標錨點（章節網址）

小標的錨點就是連結 `#` 後面那一段，決定「點連結能不能直接跳到那一小段」。
**錨點一旦發布就不能改**：`#` 後面那段瀏覽器不會送到伺服器，轉址規則看不到它，
所以改掉等於讓所有指向該段落的外部連結落在文章開頭，而且救不回來。

## 兩套規則

| | 舊的 128 篇 | 從現在開始的新文章 |
|---|---|---|
| front matter | `legacyAnchors: true` | 不要加這個欄位 |
| 產生方式 | 完全複刻 Hexo 當年的規則 | 見下方「新規則」 |
| 為什麼 | 線上已經有 1,622 個錨點在用 | 沒有歷史包袱，用比較好的寫法 |

`legacyAnchors: true` **只能出現在搬家過來的舊文章**。新文章加了它，等於自願繼承
一套沒必要的舊行為（保留大小寫、全形標點原樣留在網址裡）。

## 新規則

`slugizeModern`（`src/utils/headingSlug.ts`）：標點與空白換成連字號、連續的合併成一個、
全形標點也一起折掉、最後轉小寫。

```
## 1.100.0 Pre-release - 2025-06-23    →  #1-100-0-pre-release-2025-06-23
## Data Tables：支援 CSV 下載            →  #data-tables-支援-csv-下載
## 什麼是 n8n？                         →  #什麼是-n8n
```

刻意不套用 Astro 內建的 github-slugger：它把標點**刪掉**而不是換成連字號，
版號 `1.100.0` 會黏成 `11000`，而且會留下 `---` 這種連續連字號。

## 想要英文錨點就自己寫一個

中文小標產生的錨點是中文，貼到別的地方會變成 `#%E4%BB%80%E9%BA%BC...`。
希望某一段的連結好讀、好分享，就在小標後面自己指定：

```markdown
## 為什麼要用 Merge 節點 {#why-merge}
```

- 只有 `{#...}` 這一段會被拿掉，小標文字照常顯示，目錄也跟著用這個錨點
- 格式限制：英文字母開頭，之後只能是英文、數字、`-`、`_`、`.`
- **選配**，沒寫就自動套新規則，不會壞掉
- 寫了就等於發布，之後不能改。只在你預期會被引用的段落寫就好

## 改動前必跑

```bash
npm run build                 # 錨點在建置時產生
npm run test:anchors          # 兩套規則 + 手寫錨點的單元測試
npm run test:anchors:internal # 站內所有 # 連結是否都指得到東西
npm run test:anchors:live     # 舊文章的錨點是否還跟線上一致（要連網）
```

`test:anchors:live` 會抓 www.darrelltw.com 逐篇比對。它有一份白名單記錄
8 個已查明、刻意不還原的差異，每筆都寫了原因；**白名單以外的任何差異都是退化**。
舊站下線之後這支就失去對照組，屆時改成比對凍結基準檔
（`tests/fixtures/frozen/build-manifest.json`）。

## 常見錯誤

**改了小標文字**：錨點跟著變，等於斷掉舊連結。真的要改標題文字又想保住錨點，
就用 `{#原本的錨點}` 把舊值釘回去。

**快速導覽的錨點對不上**：`{% quickNav %}` 裡的 `anchor` 是手寫的，改小標時很容易忘記同步。
`npm run test:anchors:internal` 就是在抓這個。

**只跑 `npm run build` 就相信結果**：Astro 有內容快取（`node_modules/.astro/data-store.json`），
改了 remark 外掛之後它可能還是給你舊的 HTML。驗證錨點相關的改動前先
`rm -f node_modules/.astro/data-store.json`。
