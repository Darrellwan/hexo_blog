## Think/Feel/Do 三問框架 {#think-feel-do}

### 概念說明

在動筆前用三個問題釐清讀者目的，確保文章有明確方向：

| 問題 | 說明 | 範例（n8n Gmail 節點教學） |
|------|------|---------------------------|
| **Think（想什麼）** | 讀完後，讀者應該理解什麼？ | 「Gmail 節點可以自動處理收信、寄信、搜尋郵件」 |
| **Feel（感受什麼）** | 讀完後，讀者應該有什麼感受？ | 「原來設定這麼簡單，我也能自動化處理郵件」 |
| **Do（做什麼）** | 讀完後，讀者應該採取什麼行動？ | 「照著步驟設定 Credentials，建立第一個郵件自動化」 |

### 使用時機

Phase 0 資料收集完成後，開始撰寫前快速回答這三個問題。

### 檢查範例

```
✅ 好的目標設定：
- Think：了解 Gmail 節點的 5 個核心功能
- Feel：覺得自動化郵件處理其實不難
- Do：設定好 OAuth，建立「新郵件自動轉發到 Slack」workflow

❌ 模糊的目標設定：
- Think：了解 Gmail 節點（太籠統）
- Feel：覺得不錯（沒有具體情緒）
- Do：使用節點（沒有具體行動）
```

## 標題公式 {#headline-formulas}

### 四種標題類型

| 類型 | 公式 | 範例 |
|------|------|------|
| **命令型** | 動詞開頭 + 具體結果 | 「用 n8n Gmail 節點自動整理收件匣」 |
| **矛盾型** | 違反直覺的陳述 | 「為什麼我不用 Zapier 處理 Gmail 自動化」 |
| **提問型** | 讀者會問的問題 | 「還在手動轉發郵件？」 |
| **痛點型** | 直擊問題 + 解決方案 | 「Gmail 信太多處理不完？n8n 幫你自動分類」 |

### 4U 公式檢查

好標題應該至少符合 2-3 個 U：

| U | 說明 | 檢查問題 |
|---|------|---------|
| **Urgent**（急迫性） | 讓人想立刻點進來 | 「為什麼現在要看這篇？」 |
| **Unique**（獨特性） | 和其他文章不同 | 「這篇有什麼別人沒講的？」 |
| **Useful**（實用性） | 看完能帶走東西 | 「讀者能學到什麼技能？」 |
| **Ultra-specific**（具體性） | 數字、步驟、範圍 | 「有沒有具體數字或範圍？」 |

### 使用時機

Step 4 產生骨架時，用這些公式產生 2-3 個標題候選，選最合適的。

### 範例對比

```
❌ 太籠統：「n8n Gmail 節點介紹」
✅ 命令型：「用 n8n Gmail 節點打造零手動郵件處理流程」
✅ 痛點型：「每天花 30 分鐘處理郵件？用 n8n 自動化省下來」
✅ 提問型：「Gmail 自動化還在用 Zapier？試試免費的 n8n」
```

## 前 50 字黃金時間 {#first-50-words}

### 概念說明

讀者在前 3 秒（約 50 字）決定要不要繼續看。開頭必須快速抓住注意力。

### 6 種 Hook 類型

| 類型 | 說明 | 範例 |
|------|------|------|
| **痛點直擊** | 點出讀者正在經歷的問題 | 「每天收到 100 封郵件，一封一封點開回覆？」 |
| **數據震撼** | 用數字引發好奇 | 「我用這個方法，每週省下 3 小時處理郵件的時間」 |
| **故事引入** | 用場景帶入 | 「上週五下午，客戶的緊急郵件被我漏掉了...」 |
| **反直覺陳述** | 挑戰既有認知 | 「自動化不是偷懶，是把時間留給更重要的事」 |
| **提問引導** | 問讀者會認同的問題 | 「有沒有想過，為什麼每天都在做重複的事？」 |
| **承諾利益** | 直接告訴讀者能獲得什麼 | 「看完這篇，你會學到 3 個 Gmail 自動化技巧」 |

### 檢查清單

- [ ] 前 50 字有沒有明確的 Hook？
- [ ] 讀者看完會想繼續嗎？
- [ ] 是不是在「暖機」而不是直接切入？

### 使用時機

寫開頭時，確保第一段就有吸引力，不要花太多篇幅在「背景介紹」。

### 範例對比

```
❌ 暖機太久：
「在這個數位時代，電子郵件已經成為我們日常工作中不可或缺的溝通工具。
隨著工作量的增加，每天需要處理的郵件數量也越來越多...」

✅ 直接切入：
「每天收 100 封郵件，一封封點開處理？
我用 n8n Gmail 節點設定自動化後，現在只需要處理真正重要的 10 封。」
```

## 填充詞檢測表 {#filler-words}

### 概念說明

填充詞會稀釋文章力道，刪掉後句子更有力。定期掃描這些詞，能顯著提升文章品質。

### 中文填充詞

| 類別 | 詞彙 | 說明 |
|------|------|------|
| **弱化鋪墊** | 基本上、實際上、事實上、老實說 | 刪掉後意思不變 |
| **冗餘說明** | 我們可以看到、值得注意的是、眾所周知 | 直接講重點 |
| **過度客氣** | 可能、或許、也許、應該 | 適量使用，太多顯得沒自信 |
| **虛詞連接** | 然後、接著、接下來 | 換行或用更具體的連接 |

### 英文填充詞（撰寫英文內容時參考）

| 類別 | 詞彙 |
|------|------|
| **弱化副詞** | very, really, actually, basically, just, simply |
| **冗餘片語** | in order to, due to the fact that, at this point in time |
| **對沖語** | kind of, sort of, I think, I believe |

### 使用時機

Step 6 執行檢查清單時，快速掃描文章是否有過多填充詞。

### ⚠️ 注意事項

1. **不是完全禁用**：適量填充詞能讓語氣更自然（尤其是中文）
2. **與 VOICE.md 互補**：VOICE.md 已列出「該避免的」，本表提供更完整的檢測詞彙
3. **上下文判斷**：有些詞在特定情境有意義，不要機械式刪除

### 範例對比

```
❌ 填充詞過多：
「基本上，我們可以看到，實際上 Gmail 節點的功能其實是蠻強大的，
然後接下來我就來介紹一下它的各種功能。」

✅ 精簡版本：
「Gmail 節點功能蠻強大的，來看看它能做什麼。」
```

## 快速自檢清單

撰寫完成後，用這份清單快速檢查：

### Think/Feel/Do
- [ ] 文章有明確的「讀者應該理解什麼」？
- [ ] 讀完後讀者會有正面感受（信心、興奮、安心）？
- [ ] 有具體的行動呼籲（CTA）？

### 標題
- [ ] 標題符合至少 2 個 U（Urgent/Unique/Useful/Ultra-specific）？
- [ ] 看標題就知道文章在講什麼？

### 開頭
- [ ] 前 50 字有明確的 Hook？
- [ ] 沒有「暖機」或冗長背景介紹？

### 填充詞
- [ ] 沒有過多「基本上」「實際上」「我們可以看到」？
- [ ] 句子精簡有力？
